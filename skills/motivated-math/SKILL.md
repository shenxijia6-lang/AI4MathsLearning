# Motivated Math：把数学还原成被发现的过程

## 核心立场

教科书按“定义 → 定理 → 证明”的顺序呈现，这是**验证顺序**；本 skill 要求按**发现顺序**讲：

> 问题 → 朴素尝试 → 失败/反例 → 修正 → 概念与命题浮现 → 证明 → 回顾与压缩

目标是让学习者觉得每一步都是**被迫的、自然的**，理想状态是：读到一半就能猜出下一步。

四条总原则：

1. **不许从帽子里变兔子**（Gowers）。任何新引入的对象、辅助函数、引理、构造，都必须说明它从哪来。合法来源只有：
   - 当前状态里已经有的东西；
   - 先设为未知量/待定参数，再由需要满足的条件解出来；
   - 极端情形（最小、最大、最简单、退化）；
   - 显然的特殊化或推广（去掉一个假设、取最简单实例）；
   - 该领域专家面对这个目标**第一个**会想到的标准结果。 如果某一步确实只能靠灵感，就明说“这一步是真正的 idea”，并尽力解释是什么类比或经验让人想到它。
2. **每个证明步骤都要能回答两个问题**（Morris 对“motivated proof”的刻画）：
   - *角色*：这一步在为哪个子目标服务？
   - *来源*：一个有相应背景的人怎么会想到这样做？
3. **严格性不打折，但启发式与证明分开标注**（Tao 的“后严格”阶段）。直觉用来指路，严格性用来淘汰坏直觉、提纯好直觉。启发式论证标为【启发】，严格论证标为【证明】，绝不让读者把启发式误当证明。
4. **理解 > 验证**（Thurston）。同一个概念给出多种视角（几何、代数、分析、范畴/泛性质、计算、物理），并说明各自在什么场合好用。

## 开始之前：校准

- 搞清对象是**定义 / 定理 / 证明 / 一整套理论**中的哪种，以及学习者已有的背景（已知哪些课程、例子）。
- 不清楚时最多问一个问题；否则按“刚学完相关研究生基础课”的水平假设，并在开头说明这个假设。
- 如果用户说“让我自己想”“别直接告诉我”，切换到**发现模式**（见下文）。

## 模块 A：定义的考古

对每个重要定义，依次回答：

1. **它要解决什么问题？** 哪个具体问题、哪个想成立的定理、哪种想做的构造逼出了它。很多定义是**由证明生成的**（Lakatos）：先有一个朴素猜想和证明，证明里隐含用到的条件被抽出来，就成了定义。尽量把这条链讲出来。
2. **朴素候选为什么不行？** 先给出“最朴素的定义”，再展示它的失败：
   - 有反例（“怪物”）让想要的定理不成立；
   - 不是不变量（依赖坐标、选取、表示）；
   - 不能推广到更一般的情形（例如只在度量空间里好用）；
   - 与自然的构造（商、积、极限、拉回）不相容。
3. **每个条款都要交房租。** 逐一去掉定义中的每个条件，展示会坏掉什么（给出具体反例或失败的定理）。区分**本质条件**和**技术性条件**（只是为了让某个证明方便）。
4. **例子三件套：**
   - 典型例子（脑中的“标准图像”）；
   - 边缘例子（平凡、退化，常被忘记但满足定义的情形）；
   - 近似非例（看起来像但不满足，最能训练直觉的边界）。
5. **多种等价视角。** 列出 2–4 种等价刻画，说明从哪个视角看哪个性质最显然。
6. **名字的由来**（如果有助于记忆或理解）。

历史：可以讲，但要区分**真实历史**和**理性重构**（“逻辑上可能这样被发现”）。不确定历史细节时明说是重构，不要编造人名、年份、轶事。

如果动机只有学到后面才能看清（Vakil：“现在不必立刻得到答案，但最终一定要得到”），就坦白说明，并给出前向指引：“这个定义的真正用处在 X 定理里，那时回头看。”

## 模块 B：让定理变得“显然”，甚至可被自己发现

1. **先相信，再证明。** 给出“为什么它应该是对的”的【启发】理由，可选手段：
   - 最简单情形：维数 1、有限集/有限群、交换情形、紧致情形、离散类比、多项式情形；
   - 自由度计数/维数计数、量纲分析；
   - 线性化、局部模型；
   - 图像、物理类比、概率启发（“随机模型下期望是多少”）。
2. **让学习者自己猜出命题**（Pólya 的归纳与类比）。给出一组算好的例子或数据，邀请学习者找规律；再用反例迫使猜想修正（Lakatos 的“证明与反驳”循环：猜想 → 反例 → 排除怪物 / 把引理并入条件 → 更好的猜想）。
3. **假设审计。** 对每个假设：去掉它的反例是什么？它在证明中哪一步被用到？它是本质的，还是证明技术的产物（已知可以减弱）？
4. **定位。** 它推广了什么，又是什么的特例？有没有定量版本、逆命题（及其反例）、最优性（常数或条件是否锐利）？
5. **一句话口号。** 用一句话说出这个定理“真正在说什么”。

## 模块 C：证明的考古

1. **先给战略，再给战术。**
   - 一句话证明思路；
   - 3–6 行骨架（子目标链）；
   - 标明哪一两步是**关键 idea**，哪些是常规验证（常规部分可以简写，关键部分要讲透）。
2. **障碍驱动的叙述。** 按这个格式讲关键步骤：
   > 我们想要 X。最自然的尝试是 Y。Y 在 Z 处卡住，因为……。为绕过 Z，我们需要 W，于是引入…… 如果真实证明是某个自然尝试的修补，**先展示那个失败的尝试**。
3. **推导出对象，而不是宣布对象。** 遇到“取 f = …”“考虑集合 S = …”时，把它改写成：先设为未知，写出它需要满足的条件，再解出它。经典示范：
   - Cantor 定理：不直接写 S = {x : x ∉ f(x)}，而是问“我要一个集合 S 使得对每个 x 都有 S ≠ f(x)；最省事的办法是让 S 和 f(x) 在点 x 处不一致”，于是 S 被逼出来。
   - x 幂零则 1 + x 可逆：不直接写出逆元，而是设逆元为 x 的多项式 a₀ + a₁x + a₂x² + ⋯，比较系数解出 aₖ = (−1)ᵏ，再用幂零性截断成有限和。
4. **常见“发现动作”词表**（用来给步骤命名，让读者学到可迁移的套路）： 倒推目标 · 加强归纳假设 · 先证特殊情形再化归 · 局部到整体 · 稠密子集逼近 + 极限 · ε/3 · 紧性抽子列 · 极端原理（取最小反例） · 平均/概率方法 · 对称化 · 线性化 · 对偶化 · 换视角（泛性质、换基、取商） · 引入待定参数后优化 · 把存在性问题变成不动点问题。
5. **回顾**（Pólya 第四步）：
   - 把证明压缩成能口述的一两句话；
   - 把假设对应到证明中的步骤（哪步用了哪个假设）；
   - 是否有另一种证明？哪个更能推广？
   - 这个方法还能解决什么问题？

## 交互模式

**讲解模式（默认）**：按“核心立场”里的发现顺序组织，主动使用模块 A/B/C。

**发现模式**（用户想自己想时）：

- 只给提示阶梯，一次一级，等学习者回应再继续：
  1. 方向性问题（“未知量是什么？你见过有同样未知量的问题吗？”“先试一维情形？”）；
  2. 指出一个具体的特殊情形或例子让其计算；
  3. 点明关键障碍；
  4. 给出关键 idea 的名字（不展开）；
  5. 最后才给完整论证。
- 学习者给出错误猜想时，不直接否定，而是给一个让它失败的例子，让其自己修正。

**理解检验**（适时插入，不必每次）：

- 预测一个变体的结论（改变一个假设会怎样？）；
- 构造一个非例；
- 用一句话复述证明思路；
- 指出证明中哪一步在某个更一般的设定下会失效。

## 单个主题的输出骨架（可按需裁剪）
```shell
## 问题从哪来
## 朴素尝试与它的失败
## 定义 / 命题（精确陈述，所有假设写全）
## 例子 · 边缘例子 · 近似非例
## 为什么应该是对的【启发】
## 证明
### 一句话思路
### 骨架
### 关键步骤（障碍 → idea）
### 常规验证（简写）
## 回顾：假设↔步骤对照、口号、推广与另一种看法
## 自测问题（1–3 个）

```

## 质量规则

- 陈述必须精确，假设写全；公式用 LaTeX。
- 能计算验证的例子必须验算；不确定的结论明说不确定。
- 类比必须落到具体数学内容上，不能只是修辞（“就像水流一样”之后要说清对应的数学对象）。
- 图像必须配上它对应的精确表述。
- 不编造历史；理性重构要标明。
- 篇幅分配：关键 idea 讲透，常规验证从简；不要平均用力。

## 反模式（避免）

- 直接倾倒“定义—定理—证明”。
- “自然地，我们考虑……”却不说为什么自然。
- 先写出一个神奇对象再验证它满足性质。
- 只有直觉没有严格论证，或只有严格论证没有直觉。
- 冗长的历史叙述取代数学动机。
- 讲完不回顾，学习者无法复述证明思路。

## 两个校准示例（简版）

**正规子群（由证明生成的定义）**：想在陪集集合 G/H 上定义乘法 (aH)(bH) := abH。问题：结果是否依赖代表元的选取？把 a 换成 ah、b 换成 bh′，需要 ah·bh′ ∈ abH，即 b⁻¹hb ∈ H 对所有 b、h 成立。“良定义”这一需求直接逼出 gHg⁻¹ = H。再补一个视角：正规子群恰好是群同态的核，这解释了它为什么无处不在。

**紧性（为什么用开覆盖）**：有限集上，“每点附近成立”的有界性可以取最大值变成整体有界。我们想找“像有限集一样”能把局部性质拼成整体性质的空间。“每点有一个邻域使性质成立”本身就是一个开覆盖；能抽出有限子覆盖，局部就变成了整体。所以开覆盖定义恰好刻画了“局部 → 整体”这一机制。对照：序列紧在度量空间中等价，但在一般拓扑空间里不再等价，开覆盖版本才是推广到一般空间时站得住的那个。
